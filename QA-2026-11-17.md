# Проверка МузЛото — 17 ноября 2026

Проверены исходники, локальная версия и опубликованная игра на GitHub Pages. Браузерные проверки выполнялись в Chrome. Проверка 12 подключений использовала отдельные контексты браузера и сетевой MQTT, без общего BroadcastChannel между участниками. Это не проверка на 12 физических телефонах.

## Исправления по результатам проверки

1. Повторная победа того же игрока на том же ходу в следующем раунде больше не подавляет экран победителя. Маркер показанного результата сбрасывается при новом раунде.
2. Разные раунды больше не объединяются в истории по имени и промежутку в 30 секунд. Сервер при загрузке различает записи по идентификаторам, сохраняя разные раунды с одинаковыми комнатой, победителем и ходом. Повторный запрос «Бинго» в уже завершённом раунде по-прежнему отклоняется.
3. Явный выход игрока уведомляет ведущего, освобождает место и закрывает каналы игрока. Повторный вход не оставляет старые соединения и таймер поиска комнаты. Исправление реализовано для MQTT/BroadcastChannel/PeerJS и Socket.IO.
4. Имена `__proto__` и `constructor` корректно записываются в рейтинг. Словарь рейтинга не наследует свойства Object.prototype.
5. Подсказка длительности учитывает фактически выбранные треки, размер карточки и режим воспроизведения. Убраны значения для старого пака из 50 песен и необоснованные гарантии о моменте победы. Время всех фрагментов при автопереходе отделено от случайной длительности до первого победителя.

Для каждого исправления сначала получена воспроизводимая ошибка, затем повторена проверка после изменения.

## Известное ограничение безопасности

GitHub Pages использует публичный MQTT-брокер и клиентский протокол без проверки криптографической подлинности сообщений комнаты. Проверка в изолированной модели транспорта подтвердила: подставленное сообщение состояния с более высокой версией принимается клиентом. Внешние чужие комнаты при проверке не использовались.

Проверки выпавших песен и победы защищают обычный игровой сценарий от ошибочных или преждевременных отметок. Они не обеспечивают защиту от намеренной подделки сетевых сообщений. Для устранения этого ограничения нужен доверенный сервис комнаты с авторизацией и проверкой прав на отправку сообщений; статическая страница и публичный брокер этого не предоставляют. Самостоятельная замена брокера или добавление публичного ключа в код не решает доверие к отправителю.

## Длительность: 43 песни, 12 игроков, вся карточка

Расчёт для независимых случайных карточек и мгновенных корректных отметок, по 30 секунд песни и 4 секунды перехода. Это вероятностная модель, а не обещание времени конкретной партии.

| Карточка | Медианный ход первой победы | Медианное время | Диапазон между 10-м и 90-м процентилями |
| --- | --- | --- | --- |
| 3×3 | 33 | 18,6 мин | 15,8–20,9 мин |
| 4×4 | 38 | 21,5 мин | 19,8–22,6 мин |

Полные песни, ручные паузы и дополнительные раунды увеличивают длительность. Один раунд с автоматическими 30-секундными фрагментами не рассчитан на час.

## Повторный запуск проверок

Нужны установленные зависимости и Chrome. Для другого расположения браузера задайте `MUZLOTO_CHROME`.

```text
npm run test:rules
npm run test:server
npm run test:browser
npm run test:cloud
```

`test:browser` сам запускает временный статический сервер. `test:server` использует отдельную временную папку со статистикой и порт 3027. `test:cloud` по умолчанию проверяет опубликованный сайт; адрес можно заменить через `MUZLOTO_AUDIT_SITE`. Для сетевых и музыкальных проверок требуется интернет. Самостоятельные сценарии проверки также запускались из временной папки; постоянные регрессионные тесты находятся в `tests/`.

Не проверены на физической технике: iPhone/Safari, Android, браузер телевизора, трансляция экрана, блокировка телефона и качество Wi-Fi на месте проведения. Внешние сервисы, домашняя сеть и устройства не дают возможности гарантировать работу при любом раскладе.
